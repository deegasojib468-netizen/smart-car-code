# 智能车按键 GPIO 设计防错 Skill

## 1. 必读规则

以后任何涉及按键 GPIO、按键映射、按键状态机触发、主板切换的任务，都必须先读取本文件。

## 2. 基本排查规则

* 先查原理图。
* 先确认按键名称。
* 先确认按键对应引脚。
* 先确认按键是上拉按下接地，还是下拉按下接 3.3V。
* 先确认引脚没有和摄像头、IMU、UART、SPI、I2C、PWM、编码器、ADC 冲突。
* 松开按键不是 3.3V 时，不允许先改状态机。
* 按下按键不是 0V 时，不允许先改状态机。

## 3. Infineon / TRAVEO GPIO 必须检查

每个按键引脚必须确认：

```text
HSIOM = HSIOM_SEL_GPIO
driveMode = CY_GPIO_DM_PULLUP
outVal = 1U
input buffer on
低电平按下
没有被后续初始化覆盖
```

禁止：

* 输出。
* 开漏输出。
* 下拉输入。
* 模拟输入。
* 外设复用。
* `gpio_set` / `gpio_write` / `gpio_toggle` / `Cy_GPIO_Write` / `Cy_GPIO_Set` / `Cy_GPIO_Clr`。

## 4. 外部上拉存在时的额外规则

如果原理图已有 4.7K 上拉到 VCC3V3，松开仍然只有 1.3V / 1.4V / 0.4V：

* 优先怀疑硬件拖低。
* 必须拔核心板隔离测试。
* 必须断电测对 GND 电阻。
* 必须检查上拉电阻、按键、焊接、污染、VCC3V3。
* 不能继续调状态机。
* 可以临时改用另一个确认正常的按键继续流程测试，但必须在状态栏保留坏引脚诊断。
* 临时绕过必须写入错误记录，不能当最终方案。

## 5. 状态机接入规则

* 电压测试通过后，才允许接入状态机。
* 事件必须使用 armed 机制，先松开再按下。
* 事件锁存后只能由对应状态消费清零。
* 不允许一进 S2/S3 因按键常低自动跳状态。
* 坏引脚只能诊断，不参与状态跳转。

## 6. 历史错误

* P06_4 / U8 曾经出现 1.4V / 0.4V，原因偏向 GPIO 输入上拉配置不完整或被覆盖。
* P20_3 / 旧主板 S3 出现 1.3V，完整 GPIO 输入上拉后仍异常，因此硬件拖低优先级更高。
* 共同经验：看到按键 L，不代表按键真的按下，必须先量电压。
